# 引入 shadcn/ui，同时保留 WeTrim 的视觉特色

引入 shadcn/ui 同时服务两个目标：统一基础组件、减少重复实现并提高后续开发效率，以及改善界面的视觉效果。保留 WeTrim 当前的纸张底色、朱红与普鲁士蓝配色及单栏连续阅读结构，允许调整字号层级、留白、按钮尺寸、圆角、边框与操作分组。

这一方向意味着需要维护纳入仓库的组件源码，并将项目主题适配到组件体系中。相较于直接采用默认外观，主题适配增加维护成本，但能延续项目已有的视觉辨识度。官方提供现有 Vite 项目的接入方式与 CSS 变量主题机制：[Vite 接入](https://ui.shadcn.com/docs/installation/vite)、[主题定制](https://ui.shadcn.com/docs/theming)。

迁移最终覆盖整个应用的通用控件与全部界面样式。全局样式统一由 Tailwind 接管，文章正文、Markdown 预览排版及纸张装饰也纳入迁移，不保留独立的传统业务 CSS 样式体系。分批交付：先按钮、输入框等基础控件，再覆盖工作台与内容块操作，最后处理弹窗和标签选择器；正文排版及装饰随所属界面一并迁移。每批同步清理被替代的旧样式，使组件统一与视觉改善覆盖日常清洗流程。

允许改善标签选择、弹窗等控件的呈现方式与键盘操作，同时保留已有业务规则：标签确认后应用、取消丢弃本次选择，替换文章需要确认，关闭预览恢复阅读位置和焦点。组件默认行为必须服从已有业务规则，包括处理中禁止关闭等约束。

现有弹窗依赖原生 dialog 的打开与关闭行为，且与焦点恢复、阅读位置和预览性能相关；迁移需遵循 [ADR-0005](0005-continuous-rendering-without-virtualization.md) 与 [ADR-0008](0008-single-editing-block.md) 的既有约束。引入新组件底层后，需要显式适配默认聚焦、关闭限制与关闭后定位的顺序，避免组件默认行为改变业务规则。

## 实施边界与验收标准

- 应用拥有的视觉规则全部通过 Tailwind 工具类及其扩展实现；CSS 入口仅保留导入、主题变量、必要动画与搜索高亮等 Tailwind 扩展定义，不把旧业务选择器整批搬进 `@layer` 或用 `@apply` 原样包装。固定内联样式改为静态类名映射；确需运行时测量的编辑器高度等值允许通过 CSS 变量交给工具类使用。
- 抓取原文及用户 Markdown 中内嵌 HTML 的样式属于内容输入，沿用现有解析与净化规则；应用的正文排版仍迁移至 Tailwind。导出产物和飞书正文不写入界面工具类或主题。
- 采用 shadcn/ui、Base UI 与 Tailwind v4。Base UI 是 shadcn 当前默认底层，本项目没有既有 Radix 依赖需要兼容；参见[官方默认底层说明](https://ui.shadcn.com/docs/changelog/2026-07-base-ui-default)。
- 完成标准包括：通用控件统一、全部应用样式完成迁移及旧规则清理；工作台、编辑态、预览、确认弹窗和飞书设置/保存界面的截图检查；键盘操作、焦点恢复、阅读位置与既有长文性能指标通过。正式交付分别运行 `verify:pr` 和 `verify:feishu`，并补跑受迁移影响的预览与弹窗专项。测试可适配新的 DOM 结构，但保留已有业务断言。

## 编辑器尺寸与字体约定

编辑器通过 `h-[var(--editor-height,auto)]` 等 Tailwind 工具类消费动态高度。每次测量前，必须先显式设置 `el.style.height = 'auto'`，再读取 `el.scrollHeight`；读取布局尺寸时同步触发布局重算（reflow），随后将测得的高度写回 `el.style.height` 与 `--editor-height`。仅修改 CSS 变量不足以保证测量时旧高度约束已解除，可能使编辑区高度被钉死，无法随内容增减。

就地编辑沿用阅读态的字体体系：段落、标题、列表、引用和表格的文本框统一使用 `font-sans`，仅代码块（`code`）使用 `font-mono`。保持字体一致可避免切换编辑态时因字宽改变而重新折行、产生视觉跳跃。涉及中文折行和高度断言时，按[浏览器验证指南](../agents/verification.md#中文字体与尺寸断言)准备字体并测量。
