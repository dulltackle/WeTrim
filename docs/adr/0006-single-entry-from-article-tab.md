# 文章只从用户已打开的文章标签页进入

WeTrim v1 只提供一个文章入口：用户在自己已经打开的公众号文章页上点击扩展图标，由 content script 读取当前页面的 DOM。不提供「在扩展页粘贴文章链接」的入口。这条选择是整个浏览器扩展形态的立论本身——借用户自己的真实浏览器会话读取用户自己已经看到的页面，反爬风险归零，正文读取只需要 `activeTab` + `scripting`，零安装警告。

粘贴链接看上去是个理所当然该有的功能，因此这里记下为什么没有它。粘贴意味着扩展必须自己去取那个页面，也就把上游 Python CLI 为之背上 Camoufox 的那条反爬赛道原样请了回来：2026-09-11 的一次实测中，一个格式合法的 `mp.weixin.qq.com/s?__biz=…` 链接在没有任何用户交互的情况下被直接 302 到验证页 `/mp/wappoc_appmsgcaptcha`。它同时要求声明 `mp.weixin.qq.com` 的 `host_permissions`，把安装警告从一条变成两条并扩大审核面（见 `docs/research/mv3-permissions-and-review.md`），还会把上游踩过的「粘贴 URL 需要归一化」那类坑重新引入。对一个面向完全不懂技术的用户的工具，「在你正在看的文章上点一下图标」也比「复制链接、切换页面、粘贴」更好教。

代价是用户无法在不打开文章的情况下清洗它，也无法从聊天记录里直接投喂链接。反悔成本不低：事后补粘贴入口要改权限、改警告面并重新过审，因此这是一次真正的取舍，不是暂缓实现。

决策来源：[决策：文章入口与不可用页面的处理](https://github.com/dulltackle/WeTrim/issues/10)。入口之外的不可用页面判定、提示口径与候选快照衔接规则以该票的解决评论为准。
