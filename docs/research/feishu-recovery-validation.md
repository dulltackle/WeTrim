## 完整 Chrome 重启与恢复

浏览器：Chrome/155.0.8059.39。不是仅重启 worker、关闭页面或重载扩展。

### 无真实凭据的存储与权限基础

报告 `storage-result-1791384720565.json`，7 项通过：初始无飞书主机权限；以 CDP 明确设置 `userGesture:false` 申请遭拒，报 `This function must be called during a user gesture`；完整退出后重新使用相同 profile 与扩展身份，固定正文、图片来源和回执结构仍在；未授予的权限仍未授予；仅移除 connection/recovery 保留 cleaning。

初次结构比较使用 JSON 字符串，受到对象键顺序影响；修正为结构深比较后通过。另一次沙箱内 Chrome 启动失败未产生有效浏览器测试，之后通过宿主审批在同一范围执行。没有自动审批拒绝或绕过审批。

这不是用户点击拒绝/允许的原生提示验收，不能证明已授权状态能跨重启保存。

### 真实记录与图片

报告 `live-restart-1791384952045.json`，8 项通过。使用独立必需主机权限扩展，不能拿它证明可选权限流程。

- 把实际分篇 ID、字段内容和图片 token 写入扩展本地存储，不存图片二进制或真实授权码。完整退出 Chrome 并重新启动后，回执结构相同，远端两篇正文、分组、序号、状态、附件关联均能核对。
- 两份已关联 PNG 下载为 HTTP 200、68 字节，重启前后 SHA-256 一致。只证明本次短时间跨度，不保证回执永久有效。
- 另建同组两篇：第一篇有图片，第二篇尚无附件。重启后从隔离源重新下载 68 字节 PNG，获得新的上传回执，关联第二篇；正文和两篇图片全部核对后，首篇写已完成并回读成功。
- 该“源”是同一测试 Base 中的官方素材下载地址，不是微信原始图片域名。验证的是不持久化图片二进制的恢复过程，文章图片域名及真实源失效仍不能由此泛化。
- 无效素材标识返回 HTTP 404，实验保持未完成，没有发完成写入。这是人为设置不可用源，不是真实文章图片自然过期。
- 定向清除本机恢复进度后，清洗会话仍在；再次只读核对，远端记录及图片仍在。实验重新注入相同核对快照仅用于验证远端，核对后再次清除，不代表产品自动恢复被用户清除的数据。

## 验证门槛与实施边界

1. **跨账号十二列副本：已完成。** 用户提供副本链接，并人工确认“保存状态”为单选、包含“未完成／已完成”，且副本分享范围受限。用户配置该副本专用授权码后，执行 `artifacts/feishu-recovery-validation/verify-cross-account-copy.py`，仅向官方 API 发送三次 GET。报告 `cross-account-12-copy-result-20261008T025206197966Z.json`（本地日期 2026-10-07）记录：身份、字段列表、空表读取均 HTTP 200、业务码 0；十二列名称唯一、字段 ID 齐全、类型匹配，无额外列，日期格式匹配，标签选项为空、记录为零。“保存状态”为类型 3，选项精确为未完成／已完成；`complete: true`。分享范围仍以用户人工确认作为证据，不是 API 检查结果。本轮未写入远端数据或修改授权码；完整目标地址仅留在本地忽略目录，不发布到 Issue。
2. **真人按需授权：最小验证门槛已完成。** 用户提供日志（UTC 2026-10-08 03:27:25 至 03:34:21，本地日期 2026-10-07）显示未授权→已授权→API 移除后未授权；授权时无凭据、无效目标请求收到 HTTP 400／业务码 9499。此响应仅证明接口可达，不唯一解释为授权码问题。移除后三个本地样本仍在；定向清除后 cleaning 保留、connection/recovery 消失。未授权时为脚本主动跳过请求，不是底层网络拦截证据。日志没有“用户动作申请”事件、完整重启或浏览器设置撤销标记，移除后也无再授权成功状态，用户随后针对原生拒绝／允许、授权与移除后的完整重启及状态保持、重新授权与浏览器设置撤销三项明确回复“这些都执行了”。这些过程以用户人工确认补齐，不冒充日志直接观察；不再要求重复验证。证据摘要及关键事件：`artifacts/feishu-recovery-validation/manual-permission-observations-20261008T033421Z.md`（非完整原日志）。
3. **同目标真实换码：已完成。** 报告 `token-rotation-20261008T033741Z.json` 保存真实前后对照：更新前原码成功读取 Base 身份、两篇原记录及两份图片；用户真实更新授权码并替换本机配置后，进程确认新旧码不同，旧码读取身份返回 HTTP 200／业务码 1011，新码身份与记录读取均 HTTP 200／业务码 0，两份图片下载均 HTTP 200、68 字节。原记录字段摘要、附件关联及图片 SHA-256 与更新前一致，`old_rejected`、`same_records_and_images`、`complete` 均为 true。验证进程正常结束，未新增旧码持久副本。本轮只读，未重建或覆盖远端记录。人员权限变动、精确传播时间、长期有效期仍无保证；1011 不唯一表示更新或关闭。
4. **目标切换的完整流程。** 有另一表读取旧记录回执的拒绝探针（`target-scope.json`），仍不能等同于正式产品切换交互。实现必须按 Base + table 隔离进度，放弃后新保存使用新标识。

## 最终结论

现有证据支持十二列模板、首篇完成判断、可选授权及保存恢复方案进入实施，不需要重开既定产品决策。数字字段归一化、字段 ID 到当前名称的映射、Base + table 隔离回执以及每次恢复前重新核对，均为实现约束。

可行性门槛已满足；正式产品仍须执行连接维护决议中的七项最小验收清单。多人并发原子性、真实网络超时后的立即可查、附件回执永久有效、全部图片源与浏览器版本兼容、人员权限变化及精确传播时延没有得到保证。这些边界已由暂停、结果待确认、冲突保护和源失效保持未完成的既定行为承接，不构成需要新产品决策的悬案。
